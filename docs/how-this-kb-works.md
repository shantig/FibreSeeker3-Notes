# How this knowledge base works

This KB is built so that a claim can always be traced to its evidence, and so
that an AI assistant can answer questions from it without inventing or
mislabelling anything. The pieces:

## 1. Sources and provenance

Every source — a web page, a manual, a slicer package, a firmware image, a live
capture from Loom — is recorded in the append-only ledger
[`sources/manifest.jsonl`](../sources/manifest.jsonl): its URL, publisher,
retrieval time, SHA-256, size, provenance class, and where the original lives.
Large or redistribution-restricted originals stay on a separate archive (the
owner's NAS); the ledger indexes them. The handling rules are in
[`sources/SOURCE_POLICY.md`](../sources/SOURCE_POLICY.md).

Because the ledger is append-only, a record keeps the file path it had when the
source was acquired. After the 2026-09-22 directory reorganization, tools resolve
those recorded paths through `tools/paths.py` (which carries the migration map
in `sources/PATH_MIGRATION_2026-09-22.json`) rather than rewriting the ledger.

## 2. The normalized data model

The Rocket and Aura slicer settings are extracted from their packages into a
deterministic **normalized entity graph**: machines, materials, profiles,
settings, and the fields on them, versioned per source, with a delta layer
recording what changed between versions and an identity layer linking the same
entity across versions. This lives under
[`data/profiles/`](../data/profiles/): `generated/` holds the canonical JSONL,
`schemas/` the JSON Schemas, and `registries/` the units/enums/aliases. The
model and workflow are documented in `data/profiles/CANONICAL_MODEL.md` and
`NORMALIZATION_WORKFLOW.md`.

An operational-knowledge corpus over bounded Anisoprint analog evidence plus
first-party FibreSeek direct evidence lives under
[`data/operational/`](../data/operational/).

## 3. The query layer

`tools/query_kb.py` answers questions against the normalized data. It builds a
disposable local SQLite index (rebuilt from the canonical JSONL; never a source
of truth) and offers **view modes** that enforce the evidence boundary:

- `FIBRESEEK_CONFIRMED` — only FibreSeek-evidenced values.
- `LINEAGE_AWARE` (default) — FibreSeek values, with Aura lineage shown as
  lineage, not as fact.
- `HISTORICAL`, `ALL_EVIDENCE` — progressively wider, always labelled.

The contract is in `data/profiles/QUERY_LAYER.md`.

## 4. The agent and LLM layers

On top of the query layer sit a deterministic query planner, compact context
packets, and a structured safety evaluator that rejects answers which would
pass off an inference or an Anisoprint-era value as FibreSeek guidance
(`data/profiles/AGENT_CONSUMPTION.md`). A live LLM can be placed inside that
deterministic envelope with bounded repair and post-render validation
(`data/profiles/LLM_EVALUATION.md`,`CONVERSATIONAL_COVERAGE.md`).

**A note on the recorded evaluations.** The committed live-evaluation results
were produced with `gpt-5.4` through isolated OpenAI Responses and Codex CLI
adapters. Those files are kept as records of experiments that actually ran, so
they name those tools; they are evidence, not a statement of current tooling.
The project is otherwise Claude-only. The query/agent layers are
transport- and model-neutral, and a Claude adapter can be added the same way.

## 5. Validation

Each layer has a checked-in validator (`tools/validate_*.py`) and unit tests
(`tools/tests/`). They fail closed when a source, classification, provenance
link, or expected count is missing. The acceptance gates and commands are listed in the repository's
agent contract.

## 6. The public copy

This repository is private and holds the full archive, including vendor
documents, raw machine captures, and private correspondence. A curated public
copy is generated by `tools/export_public.py` under the allowlist and redaction
rules in `tools/public_export.json`, and checked by
`tools/check_public_tree.py`, which fails closed on any residual personal or
machine-identifying data before anything is published.
