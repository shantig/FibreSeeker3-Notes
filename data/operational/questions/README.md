# FibreSeek Unknowns / Validation Backlog

The 22 open questions are generated from analog evidence but are not evidence
that FibreSeek shares the motivating behavior. Each question states why it
matters, links the exact analog records, describes resolving evidence, and uses
one resolution class:

- `STATIC_FIRST_PARTY` — existing first-party documents or static packages.
- `VENDOR_CONFIRMATION` — owner-approved vendor clarification.
- `OFFLINE_RUNTIME_TEST` — separately authorized Rocket execution without a printer.
- `PHYSICAL_EXPERIMENT` — separately designed and authorized hardware work.

Phase 2F-A performs none of the latter three activities. The backlog prioritizes
minimum path geometry, nozzle registration, macrolayer/Z scheduling,
cutter/restart precedence and dead distances, diagnostics, material
qualification, and maintenance.

Phase 2F-B does not rewrite this historical analog-generated backlog. Its direct
FibreSeek/Rocket status overlay is
`../fibreseek/questions/fsq_status.jsonl`; methodology and status definitions
are in `../PHASE_2FB.md`.
